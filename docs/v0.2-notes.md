# Menagerie v0.2 design notes — keyboard, heap, shell

## Keyboard (IRQ1, PS/2 via i8042)

- IRQ1 handler is plain Orum (`on_irq`, vector 33): `inb(0x60)`,
  scancode set 1 → ASCII via two 128-byte tables in lowmem
  (0x76B4 unshifted, 0x7734 shifted), shift press/release tracked at
  0x7524, 0xE0 extended prefix skipped via flag at 0x752C.
- Decoded bytes go into a 256-byte ring buffer at 0x7534
  (head 0x7504, tail 0x750C). The kernel polls it; the shell blocks
  on it (hlt loop). No USB yet — xHCI is the real-hardware path.
- Shift+letter produces lowercase (no uppercase glyphs in the font;
  documented, not a bug).

## Heap

- The Orum compiler emits `__orum_heap_start`/`__orum_heap_end` as
  UND externs. `boot/mkcustom.py::apply_heap_relocs` resolves the
  two RELA entries to 0x2000000–0x3000000 (16MB, identity-mapped).
- v0.2 allocator: bump pointer (`heap_ptr` in .data). No free —
  the upgrade path is a free-list; the kernel self-test
  (`list[int]()`, push 100, verify pattern) prints "heap ok".

## Shell

- First real Orum program on Menagerie. Prompt `> `, 128-byte line
  buffer at 0x7634, backspace editing, 120-char limit, enter dispatches.
- Aiden's LOCKED set: `say` (echo) and `help` (command list) and
  `clear` (fill background) work. `restart` reboots via i8042
  (`outb(0x64,0xFE)`). The other 13 (list/run/where/copy/move/burn/
  newdir/show/page/edit/match/search/tasks/stop/space/size) and `off`
  answer honestly: "not implemented yet: <cmd>" — no filesystem,
  no ACPI, no faking it. Unknown input: "unknown command: <cmd>".
- Console: 128x48 text cells (8x16 glyphs on 1024x768).
  `draw_glyph_at(ch, x, y)` and `clear_cell(x, y)` take CHARACTER
  coordinates — pixel row = y*16+row, pixel col = x*8+col.
  (v0.2 bug fixed: these used y+row, which only worked for row 0.)
